# 后端接入状态

后端项目：`../kui-admin-api`，Cloudoll 4.3.0 + MySQL。数据库配置及初始化以该项目 README 为准。

业务 API 已迁移到实体查询：关联筛选、聚合、分页、行锁、原子库存更新和设置 upsert；HTTP 服务使用默认数据源。此内部迁移不改变前端接口契约，也不代表下方待接入页面已完成。

## 已接入

- 账号密码登录、真实会话与用户权限；登录页不预填任何凭证，也没有手机号/第三方入口——后端没有这些服务，页面上就不摆。
- access token 过期刷新，保存轮换后的 refresh token，并发刷新合并，退出期间不恢复旧会话。
- 服务端退出撤销会话；失败时清除本地状态并明确提示服务端未确认。
- 导航与权限：从 `/navigation` 获取允许项，仅匹配前端编译好的路由，不执行远程组件路径。导航时重新获取 `/auth/me`，不把本地权限缓存当最终授权。
- 个人中心的显示名、邮箱、手机、个人简介保存到 `PUT /auth/me`；上次登录、登录地点、所属部门名读的是同一份 `/auth/me` 响应里的 `lastLoginAt`/`lastLoginIp`/`departmentName`。列里是 `NULL` 时写"首次登录""暂未提供"，账户快照里根本没带这个键时另写一句，两者不混为一谈。
- 个人中心的「登录密码·修改」是一个真弹窗，提交 `POST /auth/password` 的 `{oldPassword, password}`：空当前密码、新密码不足 12 位、两次输入不一致都在本地先拦住、不消耗请求；服务端拒绝时把原话显示在弹窗内、输入保留，因为改密接口不写任何状态，重试不需要重新填一遍。成功时服务端已经换掉哈希并撤销该账号的全部会话，所以本地直接结束会话跳登录页，而不是拿着一个服务端已经不认的 token 停在原页面。「安全邮箱·更换」「绑定手机·更换」不做第二个弹窗：这两个值就是基本信息表单在 `PUT /auth/me` 里写的那两列，按钮切到「基本信息」页签并把光标放进对应的输入框（切换与聚焦之间隔一次 `nextTick`，未激活的页签面板是 `display: none`，聚焦一个看不见的输入框是空操作）。账号安全面板因此只剩三行——登录密码、安全邮箱、绑定手机，各自都真做一件事；原来的「两步验证·开启」已删除，后端没有这项服务，页面上不摆一个按下只会说「待接入」的按钮。「偏好设置」页签同理只剩两个真有人读的开关：深色模式交给主题 store，页面水印由 `src/App.vue` 判定，原来的「桌面通知」已删——没有任何代码消费它，浏览器通知权限也从未申请过。
- 开发代理 `/api` → `http://127.0.0.1:9001`。生产环境配置同源反向代理，后端默认不跨域放行。
- 客户列表与详情：服务端分页、名称/联系人/城市搜索、等级/状态筛选、新建与资料编辑；不存在的客户显示错误，不回退到演示客户。移除没有统计依据的客户价值、健康度和业务动态。
- 客户页四张卡片读 `/customers/summary` 的一次聚合，每个数字都是这张列表对同一个问题给出的行集：`客户总数` 是无筛选列表的总数，`战略客户` 是等级下拉选中「战略客户」时列表给出的总数，`客户年价值` 是年价值这一列在每一页上的合计而不是屏幕上一页的和，`本月新增`/`上月新增` 按 UTC 自然月统计每行自己的 `createdAt`——卡片上的月份和日期列读出来的必须是同一个月，所以窗口用的是自然月而不是滚动 30 天。「较上月」跟 `beforeThisMonth`（上月末那一刻的行数）比，本月的删除不会把基线一起挪走；上月末还没有客户时写「上月末还没有客户」而不是 0%。「贡献 X% 收入」只在年价值不为 0 时计算，金额为 0 时写「客户订单还没有收入」；金额按约定仍是两位小数字符串，换算成「万」用 big.js 而不是浮点除法。聚合读取失败时整排卡片不出现，并用服务端原话说明原因，不编造数字；新建客户后列表与这组数字一起重读。列表自己的「N 家客户」计数跟随筛选，与卡片不跟随筛选是有意的两个数字。
- 商品列表：服务端分页、名称/SKU 搜索、分类/上下架筛选、新建、编辑、上下架及批量下架；金额以字符串提交，失败保留表单。上下架使用独立接口，不回写列表中的旧库存；批量操作失败明确显示已完成数量并重新查询。
- 列表请求忽略过期响应，支持失败重试与缓存页面重新激活加载。写操作入口跟随真实权限，最终仍由服务端授权。
- 列表上的外键一律显示名字而不是主键：`ResourceDefinition.derived` 声明「只有服务端算得出来、谁也不会往表单里打」的列，它们进表格不进表单，后端 `RESOURCE_LOOKUPS` / `RESOURCE_LINK_NAMES` 在列表和详情两个通道上一起解析，因此同一行不会在抽屉里换成另一串字符。目前是用户页的部门、角色、最近登录，角色页的成员数与创建时间，审批页的申请人、部门、申请时间，客户页的负责人，操作日志的操作人，任务页的负责人——后两行的 id 都是服务端在建单时盖的章（`owner_id`），表单里没有对应字段，也没人选过它。可编辑的 id 列继续 `hidden`，页面上不再出现 32 位十六进制；解析不到、或这件事根本没发生过，格子里写「—」而不是 `null`、`1970-01-01` 或留白。
- 加载态不替换正文：一次读取在路上时，卡片外框、栅格位置与不依赖读取的内容（快捷入口按权限、静态口径说明）照常渲染，还没读到的数字用 `Skeleton` 占在自己的位置上；本身会报等待的组件用自己的状态——表格是 `Table :loading`，趋势图是 ECharts 的 `:loading`（`src/components/charts/TrendChart.vue` 为此透传 `loading`）。骨架一律 `:delay="0"`：先空一帧再出骨架，屏幕上仍然是「UI 没了」。等待期间页面上不出现 `¥`、不出现 0、也不出现「当前账号无法读取」——那是一句还没向服务端问过的权限判断。全仓已按此口径改造完：工作台、经营分析与 `TrendChart`/`DonutChart`、客户 / 项目成员 / 订单三张详情页、部门维护、系统设置、日程议程、通知列表、任务看板，以及通用资源管理器（列表用 `Table :loading`，详情抽屉的表单用骨架，计数条改走 `ListPanel` 的 `#summary` 槽，好让「共 N 条」在读取到货前占位而不是报 0）。`src/pages` 与 `src/components` 里已不再有用一句提示文字替换正文的加载态。读取被拒时只显示服务端那句话：等待中的骨架不会跟着一起画出来（`#summary` 槽整条 `v-if="!error"`，被拒后既不报 0 也不继续装等待）。同一口径现已铺到五张自建列表页：客户与订单在聚合到货前画四张卡片外形的空框（`:rows="2"`，142px 对真卡片的 131px），聚合被拒时不画；商品、售后、操作日志只有计数条等待。两处只有量盒子才会发现的坑：`#summary` 是 `white-space: nowrap` 的收缩盒子，骨架的标题条按百分比算宽，放进去量出来是 0×68——屏幕上看不见，白占三行的高度，所以计数条骨架自带 `min-width: 100px` 并用 `:title-width="0"` 只留一行；分页器 `Page` 的 `showTotal` 会把同一个总数用英文再报一遍，在途时就是「Total 0 items」，列表页一律 `:show-total="false"`（中文那句计数条已经说了），通知列表那台是唯一报总数的地方，改成 `:show-total="!loading"` 等答案而不是报 0。
- 写操作被服务端拒绝时一律可见：请求层只对超时和网络错误发声，4xx/5xx 是以异常抛给页面的，因此每个写入入口要么把服务端原话显示在表单/弹窗内（日程抽屉、部门弹窗、项目成员等），要么用 `src/utils/report-failure.ts` 提示后保留输入；只有 401 不再重复提示，因为请求层已经在结束会话并跳转登录页。读操作仍可静默降级（项目目录、看板项目名、关联选项），那类失败由页面自己说明。
- 订单列表与详情：服务端分页、关键词/状态筛选、支付方式与来源的下拉候选值来自 `GET /orders/facets`（读的是本账号看得见的订单实际写入的值，`待支付` 那类空值不进候选）、UTC 下单日期筛选；真实关闭、优惠调整、收货地址、备注、部分发货、收款结果登记、签收登记、售后申请。删除原订单演示数组和 localStorage store，不存在的订单显示错误，详情响应不会串到其他订单。金额来自服务端的两位小数字符串，显示时用 `src/utils/common.ts::formatMoney` 分组。
- 售后：服务端分页与筛选、审核/驳回、外部退款凭证登记；失败保留输入，不修改本地订单履约状态。退款凭证号用于服务端幂等处理，不执行实际转账。
- 订单页四张卡片读 `/orders/summary` 的一次聚合：`今日订单` 是服务端 UTC 当日的订单数，`待付款`/`待发货` 就是列表筛选的 `status=pending`/`status=paid`（这本状态字典里"已付款未发货"写作 `paid`），`退款申请` 是待审核的售后申请数——账号没有售后读取权限时卡片显示"当前账号无法读取售后"而不是 0，聚合接口失败时整排卡片不出现，也不编造数字。关闭订单会同时重读列表与这组数字。导出订单走 `GET /orders`：按屏幕上这套筛选逐页翻到 100 条一页（服务端每页上限就是 100），到 1000 条停止并说明更早的订单不在文件里，空结果不下文件；候选值读取失败时两个下拉是空的并说明原因，列表照常。固定时间轴仍是移除状态。前端目前没有新建订单入口，订单创建 API 已实现；并未将其描述为已接入页面。
- 订单详情的四段进度条只有能读到时间的段才写时间：`提交订单` 用 `orders.created_at`、`登记收款` 用 `payment_at`，`商品出库` 用 `shipments[0].createdAt`——服务端 `_hydrate` 按 `created_at asc, id asc` 返回包裹，第 0 个就是最先出库的那一件，后面的包裹不会把这一段推后（这一段记的是货什么时候开始走，不是发了几箱）。`确认收货` 用 `orders.received_at`：这一列只由 `POST /orders/{id}/receive` 写，页面上的入口在 `status === 'shipped'` 且账号有 `order:receive` 时出现，确认框让服务端记下这一刻，不让操作员填时间——签收时间是履约的结果，不是一个可选的表单字段。这一列存在之前就已经是 `completed` 的单子没有签收时刻可读，时间轴那一格与「订单信息」里的 签收时间 一起留空/写「尚未签收」，不用 `updated_at` 顶替：改价、备注任何一次编辑都会推着它走，把它指成物流事件等于说一件没发生过的事。导出的 CSV 同多一列 `签收时间 (UTC)`，写的仍是服务端原样，没签收的单子留空格而不是 `0`。
- 工作台：整页由一次 `GET /dashboard` 撑起。四张头部卡各自钉住一个窗口——今日订单（较昨日同时段）、本月净收款（较上月同期）、本月新增客户（较上月同期）、待审批申请——窗口边界与百分比都由服务端算，`change` 为空时卡片写"昨日同时段还没有订单"这类原话，不画一个没人除过的 0%。近 7 天收款趋势画的是 `/analytics` 同一批日桶，卡上的七日收款就是这七个桶用 `big.js` 相加；项目进度面板取最近截止的四条，负责团队是一次批量解析的部门名（没有部门就写"未分配团队"），状态词取自 `src/api/workspace.ts::projectStatusOptions`，不在工作台再抄一份；近期活动是操作日志最新的六行，模块与操作内容同样来自服务端字典。四类待办队列（待发货、待审批、待售后、逾期任务）与两个面板按各自列表的读取权限收口：读不到的是 `null`，页面保留这一行并写"无读取权限"/"当前账号无法读取…"，读得到却没有数据才是 0 / "暂无…"。数据总览仍保留六项累计（金额分组、计数保持纯数字），快捷入口只摆这个账号打得开的页面。头部日期标签写 UTC 那天，因为今日/本月就是在 UTC 日切的，跟着浏览器时区走会让同一屏出现两个日期。
- 经营分析：读取 `/analytics`，7 天/30 天按 UTC 自然日、今年按自然月分桶，与前一等长周期或去年同期对比；收入趋势、订单渠道、支付方式、履约漏斗和 CSV 导出全部来自真实订单聚合。上期没有可比数据时显示"上期无可比数据"，客单价和退款率在没有已支付订单/收款时显示为不可计算而不是 0。移除没有数据表支撑的访问设备面板。数据源只有 `src/api/reports.ts::loadAnalyticsReport` 一处，它请求的就是 `/analytics`，窗口计算与同比都在服务端（`admin_api/analytics.py`），页面不参与算数。
- 项目、任务、日程：采用统一的服务端分页列表与详情/编辑表单，接入新建、编辑、删除；任务可选择或清空项目关联。日期/时间按接口原值传递，不做隐式时区转换。原演示看板与里程碑展示未作为已接入功能保留。
- 日程月历：`/calendar` 的"月历 / 列表"两种视图共用同一份日程数据。月历按当前显示月份向 `GET /calendar` 请求 `dateFrom`/`dateTo` 整月窗口（每页 100 条翻到取完，读到 500 条停止并显示"本月共 X 条日程，已读取 Y 条；按分类筛选可以缩小范围"，不静默当作全部），切换月份或分类都会重新查询，顺序来自服务端的日期+时间排序而不是记录 ID。日期窗口按本地历法算出当月首尾，闰年 2 月单独测过。网格选中日期后右侧列出当天日程，点条目看详情、可编辑/删除，新建按选中日期预填；写操作走 `POST/PUT/DELETE /calendar`，时间以 `HH:mm` 提交、展示时去掉接口返回的秒。入口只按 `calendar:write`/`calendar:delete` 显示，没有权限时页面说明原因；读取失败显示错误与重试，不回退演示日程。列表视图复用通用资源管理器，只在切到列表时挂载，看月历不会重复请求。
- 任务看板：`/tasks` 的"列表 / 看板"两种视图共用同一份数据契约，看板列即 `todo/doing/review/done` 四档。卡片来自 `GET /tasks` 分页拉全（服务端每页上限 100，超过 500 条时明确显示"仅统计前 500 条"而不是静默截断），关键词搜索走服务端，优先级与项目筛选在已加载的这批数据里做客户端过滤，不再发请求。拖拽调用 `POST /tasks/{id}/status`：Kui Kanban 完全受控，卡片落列由父组件替换数组后才成立，因此写入采用乐观改列→以接口返回的实际状态回填→失败回退原列并显示服务端报错；一次只允许一张卡片在途。没有 `task:write` 的账号看板只读（`draggable=false`）并显示原因。项目名仅在 `project:read` 允许时解析，否则卡片写"未命名项目"，不拿 ID 冒充名称。
- 项目成员：列表行的"成员"入口进入 `/project/{id}`，读取 `GET /projects/{id}/members`，保存走 `PUT`（整份替换语义，提示文案明确"未选中的人将离开项目"）。负责人由项目资料决定，页面只展示不修改。可选人员来自 `/users` 分页目录并过滤停用账号；目录不可用（缺 `system:user:read` 或请求失败）时页面降级：仍在名单里的人可以继续取消勾选以移除，页面顶部说明无法搜索新成员，不把空目录伪装成"没有可选的人"。待保存差异按新增/移除人数显示，失败保留草稿。
- 审批：真实申请列表、提交、待审编辑、审核/驳回及备注；审核后只读、不提供删除入口，禁止自审仍由服务端强制执行。金额保持十进制字符串。
- 系统用户/角色：真实分页、详情、保存、启停及角色/权限/部门关联；写入入口与服务端一致限制为全权限管理员。编辑密码留空不修改，清空关联显式提交 `null` 或空数组。初始管理员及其角色的保护仍由服务端执行。
- 部门维护：`/system/departments` 读取 `GET /departments` 的整份部门目录（无分页，搜索在这批数据里按名称过滤，不再发请求），新增与改名走 `POST/PUT /departments`，删除走 `DELETE /departments/{id}`。写入按钮与服务端一样只认完整管理员（`*`），其他账号看到只读说明。名称去空格后提交，空名称与重名在本地先拦住、不消耗请求；被拒绝的写入把服务端原话显示在表单下方并保留输入。删除若返回 409，页面直接展示服务端给出的表名与条数（例如"2 tasks record(s) still belong to this department"），确认后不刷新、不假装删掉。
- 系统菜单：使用真实的路由、上级菜单、权限码、排序和可见状态字段，接入新建/编辑/删除；菜单树防循环由服务端校验。导航在下一次路由切换时重新读取，不执行远程组件地址。
- 操作日志：只读服务端审计记录和分页，使用实际操作人/资源/请求 ID 与 UTC 时间，不保留虚构的 IP、设备或登录结果。
- 系统设置：读取并保存 `/settings`；草稿与已保存设置分离，失败不提示成功、不应用未保存主题；恢复默认仅填充草稿，仍需保存。无后端实现的通知订阅策略已移除。组织语言/时区保存为配置，不冒充已经切换当前浏览器偏好。无设置读取权限的用户使用部署默认展示配置。

## 待接入

这个分支没有离线数据：页面不带任何自带数据源，也没有能切回本地数字的开关。后端不可用时每个入口显示的是加载失败与重试，而不是空列表，更不是编出来的一组数字——`GET /api/health` 是区分"没起后端"和"这个账号读不到"的第一步。剩下的待接入项因此全部在服务端一侧：项目里程碑与任务在同一状态列内的排序缺表和排序列，附件上传缺存储入口，短信验证码与第三方登录缺服务（登录页相应地只留账号密码）。

接口模式下 `/data/analytics`、`/system/departments` 依赖后端 `menus` 表有该路由，[002_analytics_menu.sql](../../kui-admin-api/admin_api/migrations/002_analytics_menu.sql) 与 [003_departments_menu.sql](../../kui-admin-api/admin_api/migrations/003_departments_menu.sql) 已提供，已部署的库要重新执行 `kui-admin migrate` 才会出现入口。两个文件里的 `sort_order` 与 `migrate.py` 的菜单初始化列表按下标对齐，新页面只能追加到列表末尾，插到中间会让全新库与升级后的库排序不一致。

客户/商品基础资料、现有订单/售后页面，以及上述工作台、协作与系统管理基础流程已接入。任务的列内排序与项目里程碑需要后端补排序列与表之后才能提供，接口目前只支持状态列之间的移动。

文案语言有两处已知限制：`src/App.vue` 在没有 `localStorage.lang` 时取 `en`，于是中文页面里 Kui 自带文案是英文（表格空态"No Data"、日期框"Select date"、抽屉"Ok/Cancel"、月历"Today / October 2026"）——这是作者定的现状，中英文切换补全之前默认保持 `en`；后端返回的错误原话也是英文（例如删除被占用项目时的"Remove the project members before deleting the project"），现在这些原文会直接进 toast 和弹窗，服务端补中文消息或前端做映射都还没做。列表视图的日程时间仍显示接口原样的 `10:00:00`，只有月历按 `HH:mm` 展示。

特别约定：金额 API 使用十进制字符串；付款和退款接口仅登记外部确认结果，不实际转账。后端暂无项目里程碑、附件上传、短信及 OAuth；对应功能需要实现真实服务后才能宣称可用。

- 金额的显示只有一条路径：`src/utils/common.ts::formatMoney`。服务端发的是 `"1234567.89"` 这样的两位小数字符串，而字符串上的 `toLocaleString()` 是 `Object.prototype` 那一个，原样把字符吐回来——所以分组必须先转成数字，同时把两位小数钉住（否则 `0.50` 会写成 `0.5`）。分隔符钉在 `en-US` 而不是跟随浏览器：应用还没有中英文切换，同一张页面在德语机器上写成 `1.234.567,89` 就没法核对，也没法在测试里断言。空值仍是空，不显示成"0.00"——服务端留空的格子不是有人付了 0 元；`—` 这类占位原样通过。计数（订单总数、客户总数、商品总数）不归这一路管，工作台上的金额卡分组而数字卡保持纯数字。`tests/format.spec.ts` 扫 `src/pages`：模板里出现 `¥` 的每一行都必须调用 `formatMoney`，页面不得再自带 `money` 辅助函数，也不得自己对金额字段写 `Number(...).toLocaleString(`。订单详情「调整后应付」的预览只在打印时分组，`big.js` 的校验与提交的 `discount` 用的仍是未分组的原值——把分组写进那个计算属性会让一次合法改价直接抛异常。运费是否收费也是一条金额判断：`src/api/commerce.ts::hasFreight` 用 `big.js` 比零，因为服务端发的是 `"0.00"` 这样的字符串，而字符串恒为真——详情页那句 `order.freight ? … : "免运费"` 的免邮分支原本永远走不到，没收运费的单子照样在标签下写着 `¥ 0.00`；判据也不许写成和字面量 `"0.00"` 比相等，因为列上 `0`、`0.0`、`0.00` 是同一张单子，空格子算免邮而不是 NaN。

- 导出的 CSV 只有一条路径：`src/utils/csv.ts`。`toCsv` 负责单元格的引号（含逗号、引号、换行的值包起来、内部引号翻倍）与 `\r\n` 的行分隔，`downloadCsv` 负责加 UTF-8 BOM（Excel 读裸 UTF-8 的 csv 会按本地老代码页解码，中文表头进表就是乱码）和释放 object URL。金额进文件时写的仍是服务端那串未分组的两小数文本，不是屏幕上的 `1,234.00`——这样的格子被重新导入就只剩 `1`；屏幕上的分组属于显示，文件里的原值属于计算。`订单号` 写完整的 32 位而不是列表上截短显示的那一段，列表显示的是方便读，文件要的是查得回去。状态列写列表标签显示的那个词而不是 `partial_shipped` 这样的码：一份表头写着「状态」、格子里写着一串英文码的文件，是同一张页面在自己跟自己说不一致。`tests/csv.spec.ts` 扫 `src`：除 `utils/csv.ts` 自己，任何文件不得再定义 `csvCell`、不得自己 `join("\r\n")`、模板里不得再出现 `\ufeff`。

- 视觉修正：Kui Vue 的 `layout="vertical"` 表单里，包裹控件的 `.k-col` 只有 `flex: 1`（作用于主轴），而行上的 `k-row-top` 用 `align-items: flex-start` 收紧交叉轴，导致 `block` 控件按自身内容宽度收缩、同一表单各字段右边界参差。根因已在库内 `components/form/styles/index.less` 用 `> .k-col { align-self: stretch }` 修复（Kui Vue 6.3.0，尚未发布到 npm），应用侧不再打补丁；用 npm 上的 6.2.2 时这条参差会重新出现。
- 本地联调库：`pnpm link ../kui-vue` 后，`vite.config.ts` 的 `resolve.dedupe` 与 `tsconfig.app.json` 里把 `vue` 指向应用自己的 `node_modules/vue` 是必需的——链接会让库从自己的 `node_modules` 解析 Vue，出现第二份 Vue 类型身份，`app.use(kui)` 和控件的 props/事件推断都会失效。库内 `types/global.d.ts` 同时增强 `vue` 和 `@vue/runtime-core` 两个模块名也是为此：只写 `@vue/runtime-core` 时，链接状态下它增强的是库自带的那份，全局注册的组件（页面里不带 import 直接写的 `<Switch>`、`<Table>`）会退化成无类型，模板内联事件参数报 `implicitly has an 'any' type`。
